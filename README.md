# 🐾 Academic Pet — тамагочи из учёбы

Питомец, который живёт твоими дедлайнами с портала Академо (uib.academo.kz).
Сдаёшь задания — он счастлив и растёт в уровне. Просрочил — ему плохо.

Сервер не нужен: всё работает на GitHub.

```
updater/                     Python: вход в Академо, обновление списка, Web Push
.github/workflows/update.yml  Запуск каждые 30 минут + публикация + keepalive
pwa/                          Приложение с питомцем (GitHub Pages)
  deadlines.json              Список дедлайнов — его обновляет workflow
data/state.json               О каких дедлайнах уже уведомляли
scripts/                      Проверка секретов, генерация VAPID-ключей
```

## Как это работает

1. **Каждые 30 минут** GitHub Actions запускает `updater/update.py`:
   - входит в Академо (логин и пароль берутся из GitHub Secrets);
   - забирает дедлайны тем же запросом, что и блок «Дедлайны» на главной
     (`study/api/academic-calendar/get-upcoming-calendar-deadline`);
   - обновляет `pwa/deadlines.json`. Дедлайн держится ещё **2 дня после срока**, потом удаляется;
   - отправляет **Web Push** о новых дедлайнах и **за 24 часа** до срока (каждое — один раз).
2. Если что-то изменилось, workflow делает коммит и заново публикует PWA. Если нет — ничего не коммитит.
3. **PWA** читает `deadlines.json`:
   - «Готово» прячет дедлайн и хранит отметку в localStorage этого устройства (есть «Вернуть»);
   - «Обновить» перечитывает файл.
4. **Keepalive.** GitHub отключает расписание в публичных репозиториях после 60 дней без активности.
   Раз в неделю workflow заново включает сам себя через API, а если коммитов не было 45 дней,
   делает пустой коммит. Руками ничего делать не нужно.
5. Если Академо не ответил или логин не подошёл, запуск падает с красным крестиком, и GitHub
   присылает письмо. Старый список при этом не трогается.

## Секреты (Settings → Secrets and variables → Actions)

| Секрет | Что это |
|---|---|
| `ACADEMO_USERNAME` | логин от Академо |
| `ACADEMO_PASSWORD` | пароль от Академо |
| `VAPID_PUBLIC_KEY` | публичный ключ Web Push (из `secrets-to-copy.txt`) |
| `VAPID_PRIVATE_KEY` | приватный ключ Web Push (из `secrets-to-copy.txt`) |
| `PUSH_SUBSCRIPTIONS` | подписки устройств: копируются в приложении (⚙ → Включить уведомления), по одной на строку |

В репозитории нет ни одного пароля, токена или ключа. Перед каждым push запускай:
```bash
python scripts/check_secrets.py
```

> Репозиторий публичный: файл `pwa/deadlines.json` со списком заданий и курсов виден всем.
> Паролей и личных данных, кроме названий заданий и курсов, в нём нет.

## Уведомления на телефоне

- **Android (Chrome):** открой сайт → ⚙ → «Включить уведомления».
- **iPhone (iOS 16.4+):** сначала «Поделиться» → «На экран «Домой»», открой приложение с иконки,
  потом ⚙ → «Включить уведомления». В обычном Safari push не работает.
- После включения скопируй подписку из приложения и добавь её в секрет `PUSH_SUBSCRIPTIONS`
  (несколько устройств — каждая подписка с новой строки).

## Локальный запуск

```bash
python -m venv updater/.venv
updater\.venv\Scripts\activate          # Windows; на Mac/Linux: source updater/.venv/bin/activate
pip install -r updater/requirements.txt pytest
copy updater\.env.example updater\.env  # впиши логин и пароль
python updater/update.py                # одна проверка, обновит pwa/deadlines.json
pytest updater/tests                    # тесты
python -m http.server 5500 --directory pwa   # PWA на http://localhost:5500
```

Новые VAPID-ключи: `python scripts/gen_vapid.py`. Ключи запишутся в `secrets-to-copy.txt`
(он в `.gitignore`), в консоль они не выводятся.

> После правок `pwa/app.js` или `pwa/style.css` подними `?v=` в `index.html` и `sw.js`
> и версию `CACHE` в `sw.js`, иначе телефон может показывать старую версию.

## Питомец

| Состояние | Когда |
|---|---|
| 😴 Спит | дедлайнов нет |
| 😊 Доволен | ближайший дедлайн дальше 3 дней |
| 😟 Переживает | что-то сдавать через 2–3 дня |
| 😱 Паника | дедлайн сегодня или завтра |
| 🤢 Болеет | есть просроченный дедлайн |

Каждое «Готово» даёт +10 XP, новый уровень каждые 50 XP.
